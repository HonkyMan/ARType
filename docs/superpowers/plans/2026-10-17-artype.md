# ARType Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Track evidence here.

**Goal:** Corporate TypeTide fork with Google login, tenant proxy and administration.
**Architecture:** Native clients → Node API → PostgreSQL and provider.
**Tech Stack:** SwiftUI, C++20/Win32, Node 24, Express, pg, Google Auth Library.
**Spec:** `docs/superpowers/specs/2026-10-17-artype-design.md`.

## Global Constraints
Provider secrets stay on server; no translation text retained. Google openid/email/profile
only. HTTPS except loopback. macOS 26+; Windows 10+. Preserve clipboard behavior.

## Review Focus
Cross-tenant IDs, simultaneous final seat/quota reservation, logout with running
requests, cancelled/expired Google pairing, provider failure after partial response.

## Tasks
- [ ] 1. Fork and brand assets: separate checkout, SVG/ICNS/ICO, own bundle identities.
- [ ] 2. Server domain model and access: migration, invitations, roles, limits,
  transaction reservations. Tests against real PostgreSQL, including concurrency.
- [ ] 3. Google/web/device sessions: verified claims, PKCE, state, CSRF, session
  revocation; HTTP tests with an isolated OAuth boundary.
- [ ] 4. Proxy and administration UI: structured translation API, server-owned
  prompts, metadata usage and CSV, cabinet with working forms and error states.
- [ ] 5. macOS account/provider/settings: Keychain token, browser pairing, organization
  selection, structured requests, no bypass cache. Xcode unit suite and build.
- [ ] 6. Windows account/provider/settings: Credential Manager, browser pairing,
  structured proxy, own branding and update URL. CI build and self-tests.
- [ ] 7. Delivery: Docker/HTTPS, backup/restore, signing build scripts, operator and
  employee guides. Local smoke and browser check; independent review.
- [ ] 8. Configure external credentials, deploy, sign installers and verify clean
  installations and live Google/provider flows when user inputs arrive.
