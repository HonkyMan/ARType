# Эксплуатация ARType

Администратор платформы управляет всеми организациями, подключениями AI,
ставкой, балансами и другими администраторами платформы. `ADMIN_EMAILS`
содержит защищённых основных администраторов. Дополнительные Google email
добавляются в разделе «Администраторы»; отзыв прав действует и на открытые
сессии. Собственные права и основной аккаунт через кабинет удалить нельзя.

Владелец управляет ролями своей организации, языками и инструкциями, видит
баланс. Администратор организации управляет рядовыми участниками, языками и
инструкциями; доступа к балансу, ставке и платформенным настройкам у него нет.
Участник использует клиент. Назначение администратора организации не даёт
прав администратора платформы. Google-вход без приглашения не даёт доступа
к организациям.

## Оплата мест и баланс

Начальная ставка — USD 5 за уникальный email в каждом tenant за календарный
месяц UTC. Администратор платформы меняет ставку в «Настройки платформы → Тариф». Подключение в
любой день оплачивается за полный месяц; один email в двух организациях
оплачивается дважды. Повторное включение в том же tenant и месяце бесплатно.
Ранее списанная стоимость сохраняется при изменении ставки. Возврата за
отключение или истечение приглашения в уже оплаченном месяце нет.

Владелец получает кабинет бесплатно и не может использовать программу до
явного подключения своего платного места кнопкой «Подключить программу».
Его роль владельца сохраняется. Ограничение мест учитывает включённые места
программы, включая действующие приглашения, без бесплатных владельцев.

При добавлении и ежемесячном продлении программа становится Active после
списания. Если средств не хватает на все ожидающие места, эти места остаются
Disabled с причиной «ожидает оплаты». Частичного продления нет. Уже оплаченные
места работают до конца текущего месяца. Отключённые места, истёкшие приглашения
и приостановленные/истёкшие организации не продлеваются.

Продление проверяется при старте API, каждую минуту, при чтении доступа и
пополнении. Простой API не переносит плату за пропущенные месяцы: после
запуска оплачивается текущий месяц. Клиенты показывают причину блокировки при
запуске; каждый перевод дополнительно проверяется сервером.

Администратор начисляет оплаченную сумму или устанавливает итоговый баланс
в разделе организации «Баланс и оплата», указав основание/номер инвойса. Корректировка записывает
разницу отдельной операцией. Журнал `balance_ledger` не допускает UPDATE/DELETE;
каждый запрос имеет idempotency key, повтор не начисляет деньги дважды.
`seat_charges` уникален по tenant/email/месяцу и хранит ставку списания.
Суммы хранятся целыми центами. «Обзор платформы» показывает фактические списания за
места, а не сумму пополнений.

Кнопка владельца «Запросить инвойс» пока рассчитывает текст запроса инвойса по
количеству мест. Она не отправляет письмо и не принимает платёж. Для будущего
эквайринга предусмотрен source `payment` в журнале: проверенный webhook должен
атомарно внести кредит с уникальным ID операции провайдера, затем запустить
сверку ожидающих мест. Платёжный шлюз и выпуск документов пока не реализованы.

Последнего действующего владельца отключить нельзя: другой владелец сначала
должен принять приглашение входом. Истёкшее приглашение можно возобновить,
отключив запись и выбрав «Пригласить снова». Приглашения резервируют места 7 дней.

Приостановка организации или отключение участника останавливает следующий
перевод. Уже отправленный провайдеру запрос может завершиться и быть учтён.
Клиент не повторяет оплачиваемые запросы автоматически и не использует кеш.
Месячная квота учитывает успешные переводы и резервы выполняющихся операций;
ошибки освобождают резерв. Частота включает неудачные принятые попытки.
Одновременно разрешены не более двух запросов сотрудника, плюс общий лимит
организации. Учёт и CSV используют UTC, календарный месяц.

```bash
docker compose ps
docker compose logs --tail=100 api web
```

`/health` проверяет API/базу; реальный Google и AI требуют отдельного входа и
перевода. Провайдер ограничен 45 секундами. Его квоты остаются внешним лимитом.
За Caddy включён TRUST_PROXY=1; порт API должен оставаться закрытым извне.
Валидные устройства имеют отдельные лимиты polling, в том числе за офисным NAT.

Производительность на целевом сервере ещё не измерена. Перед массовой выдачей
проверьте ожидаемые параллельность/длину текстов. Атомарные PostgreSQL-резервы
работают между API-репликами; анонимный ограничитель входа хранится в памяти
процесса и при масштабировании дополняется ограничителем входного трафика.

## Копии и восстановление

```bash
deployment/backup.sh /srv/backups/artype
deployment/restore.sh /srv/backups/artype/backup.dump --replace-database
```

Восстановление заменяет базу, останавливает API/web на время операции.
В локальном режиме без Caddy останавливается только API; после восстановления
возобновляются только сервисы, которые работали до него. Compose-режим берётся
из `COMPOSE_FILE` в `.env`, поэтому backup/restore одинаковы для обоих режимов.
Проверяйте восстановление на отдельной инсталляции. Дамп содержит email,
memberships и хеши сессий — ограничьте права, храните копию вне этого сервера.
Отдельно защищённо сохраните `.env` и доступы Google/подписи. В `.env` находится
CREDENTIAL_ENCRYPTION_KEY для AI-ключей из кабинета. Без прежнего ключа
восстановленная база не сможет их расшифровать; потребуется ввести ключи заново.
Не генерируйте новый CREDENTIAL_ENCRYPTION_KEY при обычном обновлении.

## Обновление и хранение

Сохраните дамп, обновите исходники до проверенного commit/tag, выполните
`docker compose up -d --build`. Начальная схема отмечена в schema_versions;
изменения выполняются отдельными версионными миграциями под транзакционной
блокировкой. Повторный запуск пропускает применённые версии; сервер отказывается
запускаться с неизвестной более новой схемой. Не откатывайте несовместимую схему без
подходящего дампа. Смена модели/инструкций не требует нового клиента; смена
домена требует пересборки и нового Google redirect URI.

Google secret и CREDENTIAL_ENCRYPTION_KEY остаются в окружении API. AI-ключи
оператор сохраняет и заменяет в разделе «AI-подключения»; они зашифрованы в базе,
значение не возвращается в браузер, изменение применяется к следующему запросу.
Уже отправленный запрос может завершиться со старым ключом. Environment
PROVIDER_KEYS поддерживается как дополнительный источник; ключ кабинета с тем же
alias имеет приоритет. После изменения `.env` пересоздайте API.

При обновлении установки, созданной до управления ключами в кабинете, добавьте
однократно сгенерированный CREDENTIAL_ENCRYPTION_KEY (64 hex-символа) в `.env`.
Новый setup.sh создаёт его автоматически и не перезаписывает существующий `.env`.
Миграция schema_versions 2 добавляет provider_credentials без изменения старых
организаций; перед обновлением сохраняйте дамп. Сессии действуют 7 дней в браузере и 30 дней на устройстве;
после истечения нужен новый вход. Просроченные сессии, OAuth states и pairing
очищаются автоматически. Usage/audit хранятся без текстов; автоматического
удаления старой технической статистики в v1 нет, срок определяет оператор.

Миграции 3/4 добавляют администраторов, метаданные подключений, баланс и места.
Существующие ключи наследуют прежние URL/модель. При первом переходе на версию 4
владелец становится бесплатным пользователем кабинета; старым обычным участникам
для программы нужен баланс. Повторное обновление уже существующей версии 4
не отключает оплаченное место владельца. Версия 5 добавляет индексы для очистки
и продления; ключи, балансы и исторические записи сохраняются.
Списания за месяцы до установки биллинга не создаются.

В разделе «AI-подключения» каждое подключение имеет URL, модель по умолчанию и
ключ. При смене URL необходимо заново ввести ключ, чтобы прежний секрет не
отправился на другой сервер без явного действия. Пустое поле ключа при смене
только модели сохраняет прежнее значение. В форме новой организации выбирается
подключение и редактируется модель; настройки применяются без перезапуска.

## Docker-комплекты

Упаковка выполняется из репозитория на машине с Git и Node 24+. Перед ней
зафиксируйте проверенные изменения. Скрипты читают версию и содержимое из HEAD
и отказываются работать при изменённых, staged или новых незакоммиченных файлах
поставки. Нативные сборки, подпись, публикация и запуск Docker автоматически
не выполняются.

```bash
scripts/package-artype-server.sh
```

Получится `build/artype/ARType-server-VERSION.tar.gz` и файл `.sha256`.
Внутри — каталог `ARType-server` с серверными исходниками, Compose,
deployment-скриптами, `VERSION`, `server/scripts/check.mjs`, документацией,
MIT license, `PACKAGE.json` и пустым `releases/manifest.json`. В PACKAGE записаны
source commit и его время. Установщиков в серверном архиве нет.

Общий pilot-комплект может включать DMG, EXE или оба файла. Сначала соберите их
для одного адреса сервиса. Перенесите Windows-установщик из `windows/build/`
машины сборки в `build/artype/windows/` машины упаковки. Пример для validation:

```bash
version="$(cat VERSION)"
node scripts/package-artype-pilot.mjs \
  --macos "build/artype/ARType-$version-macos-arm64-UNSIGNED-VALIDATION.dmg" \
  --windows "build/artype/windows/ARType-Setup-$version-UNSIGNED-VALIDATION.exe" \
  --service-url http://127.0.0.1:8080 \
  --signing unsigned-validation
```

Получится `build/artype/ARType-pilot-VERSION.tar.gz` с тем же каталогом
`ARType-server`, а также `releases/` с указанными установщиками и manifest.
Ненужный `--macos` или `--windows` можно опустить. Без обоих флагов комплект
содержит пустой manifest. `--out DIRECTORY` меняет каталог результата.

Manifest содержит платформу, версию из HEAD, размер, SHA-256, адрес сервиса и
заявленное состояние подписи. Скрипт вычисляет хеши скопированных файлов, но
не проверяет встроенный URL или сертификат установщика: они должны пройти
платформенную приёмку до упаковки. `--signing signed` допустим только для
проверенных подписанных пакетов с публичным HTTPS-адресом. Локальные unsigned
установщики работают с loopback только на компьютере с сервером.

Одинаковые HEAD, байты установщиков, параметры и версии Git/Node дают одинаковый
SHA-256 архива.
Сборка самих нативных установщиков не обещает побайтовую воспроизводимость.
Проверка SHA-256 подтверждает целостность, а не доверие к источнику загрузки.
Локальные `.env`, OAuth JSON и директории сборки автоматически не включаются;
подозрительные имена секретных файлов внутри отслеживаемых исходников
блокируют упаковку.

После проверки контрольной суммы распакуйте один из архивов, перейдите в
`ARType-server` и выполните настройку:

```bash
deployment/setup.sh --google-json /secure/google-client.json --admin-email admin@example.com
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Подставьте путь к своему Google client JSON и свой email. Добавьте
`--domain translate.example.com` для HTTPS/Caddy. Без домена выбран локальный
Compose. Setup создаёт приватный `.env` и не перезаписывает существующий.
На сервере нужен Docker Compose; Node установленного хоста не требуется.
Первое получение образов и `npm ci` при сборке требуют интернет.
Google redirect URI, DNS, ключ провайдера и реальные проверки входа/перевода
выполняются отдельно; архив не содержит этих секретов.

## Публикация установщиков

Оба Compose-режима монтируют `./releases` в API только для чтения. Публикуются
только файлы из `releases/manifest.json`; загрузка требует входа в кабинет.
Страница «Установка и помощь» показывает платформу, версию, подпись, адрес
сервиса и SHA-256. Пустой каталог показывает, что установщики ещё не размещены.

```bash
node deployment/publish-downloads.mjs \
  --macos "build/artype/ARType-$(cat VERSION)-macos-arm64-UNSIGNED-VALIDATION.dmg" \
  --windows "build/artype/windows/ARType-Setup-$(cat VERSION)-UNSIGNED-VALIDATION.exe" \
  --version "$(cat VERSION)" --service-url http://127.0.0.1:8080 \
  --signing unsigned-validation
```

Команда требует Node 24+; её также можно выполнить через образ `node:24` с
проектом, смонтированным в `/work`. Это отдельная операция для уже развёрнутого
сервера: она копирует явно указанные файлы и заменяет manifest. Серверный архив
содержит пустой `releases`; pilot-архив содержит только переданные упаковщику
установщики. После замены файлов не нужен рестарт API.
Для внешней раздачи сначала выберите HTTPS-домен и пересоберите клиенты с этим
адресом. Для обычного запуска без предупреждений ОС нужны сертификаты подписи
и notarization macOS. Локальные unsigned пакеты предназначены для пилота.
